# Rust MCP Server Development Best Practices (rmcp 3.x)

> **IMPORTANT:** This document describes **rmcp 3.x** (target: `rmcp = "3.5.0"` per `Cargo.toml`).
> The crate is **not yet vendored locally** — the cargo cache only contains `0.8.5`.
> The implementer **must re-verify against 3.5.0 source** before writing the adapter.
> Every symbol below comes from the [rmcp main-branch README](https://raw.githubusercontent.com/modelcontextprotocol/rust-sdk/refs/heads/main/README.md); if the README does not mention something, it is noted explicitly.

This guide provides best practices for building Model Context Protocol (MCP) servers using the official Rust SDK (`rmcp` 3.x).

## Server Implementation (rmcp 3.x)

### Basic Server Setup — stdio Transport

The README shows the stdio transport is a **function** returning a `(stdin, stdout)` tuple, not a struct constructor.
It requires the `transport-io` feature.

```rust
use rmcp::{ServiceExt, transport::stdio};

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    tracing_subscriber::fmt::init();

    let service = MyServerHandler::new().serve(stdio()).await?;
    service.waiting().await?;

    Ok(())
}
```

**Key differences from 0.8.x:**
| 0.8.x | 3.x (README) |
|-------|--------------|
| `StdioTransport::new()` | `transport::stdio()` — function returning `(tokio::io::Stdin, tokio::io::Stdout)` |
| `Server::builder().with_handler(...).build(transport)` | `handler.serve(transport).await?` via `ServiceExt` |
| `server.run(signal::ctrl_c()).await?` | `service.waiting().await?` |

### ServerHandler and Server Construction

Implement `ServerHandler` and return `ServerConfig` from `get_info()`.
The README shows `ServerConfig::new(ServerCapabilities::builder()...build())`.

```rust
use rmcp::{
    handler::server::ServerHandler,
    model::{ServerCapabilities, ServerConfig, ServerInfo},
    service::RequestContext,
    ErrorData as McpError,
    RoleServer,
};

#[derive(Clone)]
pub struct MyServerHandler {
    // Tool router generated by #[tool_router] macro
}

impl MyServerHandler {
    pub fn new() -> Self {
        Self {}
    }
}

impl ServerHandler for MyServerHandler {
    fn get_info(&self) -> ServerConfig {
        ServerConfig::new(
            ServerCapabilities::builder()
                .enable_tools()
                .enable_tool_list_changed()
                .build(),
        )
    }

    // Optional: handle initialize completion (legacy clients)
    async fn on_initialized(
        &self,
        _context: rmcp::service::NotificationContext<RoleServer>,
    ) {
        // Server ready to receive requests
    }
}
```

**Critical notes from README:**
- `get_info()` returns **`ServerConfig`**, **not** `ServerInfo` (0.8.x used `ServerInfo`).
- `ServerCapabilities` is at `rmcp::model::ServerCapabilities` (not `rmcp::protocol::`).
- Macros `#[tool_handler]` / `#[prompt_handler]` set capability flags automatically when used.

### Tool Macros — The Main 3.x API Change

The `rmcp-macros` crate provides declarative tool wiring.
Three macros:

| Macro | Purpose |
|-------|---------|
| `#[tool_router]` | Generates a tool router on the impl block; collects `#[tool]` methods |
| `#[tool]` | Marks a method as an MCP tool; infers `inputSchema` from parameter struct |
| `#[tool_handler]` | Implements `ServerHandler` boilerplate (list_tools, call_tool) automatically |

**Shorthand for tools-only servers:** `#[tool_router(server_handler)]` skips the separate `ServerHandler` impl entirely.

```rust
use rmcp::{
    handler::server::wrapper::Parameters,
    schemars,
    tool,
    tool_router,
    ServiceExt,
    transport::stdio,
};

#[derive(Debug, serde::Deserialize, schemars::JsonSchema)]
struct AddParams {
    a: i32,
    b: i32,
}

#[derive(Clone)]
struct Calculator;

#[tool_router(server_handler)]
impl Calculator {
    #[tool(description = "Add two numbers")]
    fn add(&self, Parameters(AddParams { a, b }): Parameters<AddParams>) -> String {
        (a + b).to_string()
    }
}

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let service = Calculator.serve(stdio()).await?;
    service.waiting().await?;
    Ok(())
}
```

**When you need custom metadata or multiple capabilities (tools + prompts), use explicit `#[tool_handler]`:**

```rust
use rmcp::{
    handler::server::wrapper::Parameters,
    schemars,
    tool,
    tool_router,
    tool_handler,
    ServerHandler,
    ServiceExt,
};

#[derive(Debug, serde::Deserialize, schemars::JsonSchema)]
struct AddParams {
    a: i32,
    b: i32,
}

#[derive(Clone)]
struct Calculator;

#[tool_router]
impl Calculator {
    #[tool(description = "Add two numbers")]
    fn add(&self, Parameters(AddParams { a, b }): Parameters<AddParams>) -> String {
        (a + b).to_string()
    }
}

#[tool_handler(name = "calculator", version = "1.0.0", instructions = "A simple calculator")]
impl ServerHandler for Calculator {}
```

**Parameter wrapper:** `Parameters<T>` (from `rmcp::handler::server::wrapper`) wraps the typed parameter struct.
The macro extracts `T` for JSON Schema generation.

**Return types:** Tool methods can return:
- `String` → auto-wrapped as `CallToolResult::success(vec![ContentBlock::text(...)])`
- `CallToolResult` directly (for rich content or errors)
- `Result<CallToolResult, McpError>` (for protocol errors)

### JSON Schema 2020-12 (SEP-2106)

Derive `schemars::JsonSchema` (re-exported as `rmcp::schemars`) on parameter structs.
Field names, types, and **doc comments** drive `inputSchema` / `outputSchema`.
The type name and its doc comment are **ignored**.

```rust
use rmcp::schemars;

#[derive(Debug, serde::Deserialize, schemars::JsonSchema)]
struct SearchParams {
    /// Full-text query.
    query: String,
    /// Maximum number of results.
    #[serde(default)]
    limit: Option<u32>,
}
```

> **SEP-2106 (2026-07-28):** `outputSchema` may now be any JSON Schema type (not just `object`), and `structuredContent` may be any JSON value.

### Tool Result Content Types — ContentBlock

Beyond plain `String`, tools return `CallToolResult` built from `Vec<ContentBlock>`:

```rust
use rmcp::model::{CallToolResult, ContentBlock, ResourceContents};

#[tool(description = "Render a chart")]
async fn chart(&self) -> Result<CallToolResult, McpError> {
    let png_base64 = render_png();
    let wav_base64 = render_wav();

    Ok(CallToolResult::success(vec![
        ContentBlock::text("Here is your chart:"),
        ContentBlock::image(png_base64, "image/png"),
        ContentBlock::audio(wav_base64, "audio/wav"),
        ContentBlock::resource(ResourceContents::text(
            "chart source data",
            "chart://last/data.csv",
        )),
    ]))
}
# fn render_png() -> String { String::new() }
# fn render_wav() -> String { String::new() }
```

**ContentBlock variants (README):**
- `ContentBlock::text(&str)`
- `ContentBlock::image(base64: &str, mime_type: &str)`
- `ContentBlock::audio(base64: &str, mime_type: &str)`
- `ContentBlock::resource(ResourceContents)` — `ResourceContents::text(text, uri)` or `ResourceContents::blob(base64, uri).with_mime_type(mime)`

### Error Handling — Two Failure Modes

The README emphasizes: **choose by whose problem it is**.

| Mode | When | Constructor | Visibility |
|------|------|-------------|------------|
| **Tool-level** | Tool ran but failed semantically (no rows, upstream 500) | `Ok(CallToolResult::error(vec![ContentBlock::text(...)]))` | Client renders your content → **user sees it** |
| **Protocol** | Server can't route/process the request at all (malformed params) | `Err(McpError::invalid_params(..))` where `McpError = rmcp::ErrorData` | Clients render opaquely → **user does NOT see your message** |

```rust
use rmcp::model::{CallToolResult, ContentBlock};
use rmcp::ErrorData as McpError;

#[tool(description = "Look up a record")]
async fn lookup(&self, Parameters(args): Parameters<LookupArgs>) -> Result<CallToolResult, McpError> {
    // Malformed request → protocol error.
    if args.query.is_empty() {
        return Err(McpError::invalid_params("query must be non-empty", None));
    }

    // Tool ran, no result → tool-level error the user should see.
    let rows = self.run_query(&args.query).await;
    if rows.is_empty() {
        return Ok(CallToolResult::error(vec![ContentBlock::text(
            format!("no rows matched '{}'", args.query),
        )]));
    }

    Ok(CallToolResult::success(vec![ContentBlock::text(format_rows(&rows))]))
}
```

## Adapter Boundary — Unit Testing Without a Protocol Server

This project's architecture places **seven tools behind a local `ToolHandler` trait with zero `rmcp` symbols below the adapter**.
That seam lets everything be unit-tested without a protocol server.

```
┌─────────────────────────────────────────────────────────────┐
│  rmcp Server (thin adapter)                                 │
│  - Implements ServerHandler                                 │
│  - Delegates to local ToolHandler trait                     │
└──────────────────────────┬──────────────────────────────────┘
                           │ zero rmcp types
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  Local ToolHandler trait (7 tools)                          │
│  - archive_info                                             │
│  - list_entries                                             │
│  - find_entries                                             │
│  - read_entry                                               │
│  - grep_archive                                             │
│  - entry_info                                               │
│  - find_by_type                                             │
│  - All params/returns are local domain types                │
└─────────────────────────────────────────────────────────────┘
```

The adapter translates `rmcp::model::CallToolRequestParams` → local `ToolHandler` calls → `CallToolResult`.
This is the **only** place `rmcp` types appear.

## Testing

### Unit Tests (Version-Independent)

Test tool logic directly via the local `ToolHandler` trait — no `rmcp` involved:

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[tokio::test]
    async fn test_archive_info() {
        let handler = TestToolHandler::new();
        let result = handler.archive_info(ArchiveInfoParams { path: "test.zip" }).await;
        assert!(result.is_ok());
    }
}
```

### Integration Tests (Requires rmcp)

Spin up the full server via `serve(stdio())` and drive it over the protocol (use a test helper that connects a client transport).
