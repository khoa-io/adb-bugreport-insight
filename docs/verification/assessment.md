# Verification assessment

## Scope and verdict

The committed set contains 32 requirements: 31 are supported by the reviewed macOS implementation and selected acceptance evidence, and REQ-CLI-03 is not demonstrated for native non-Unix response-pipe failure behavior.
The verdict covers the named fixtures, reviewed code and executed platforms; it does not establish unconditional cross-platform conformance or every Android/OEM layout.
Deferred proposals remain outside the assessment.

The [recorded requirement walkthrough](../../verification/results/software-qualification.md) owns tested revision, execution dates, toolchain, environment and individual assertions.
The [missing-memory-provenance regression](../../verification/results/missing-memory-provenance.md) supplements that walkthrough for supported reports with absent memory clocks; its recorded workspace run passes 202 tests, formatting, build and Clippy.
These are reused execution records, not a new software run performed while editing this page.
The [raised-limit/scoped-insight result](../../verification/results/force-and-scoped-insight-mcp.md) adds a fresh 222-test workspace run and targeted acceptance for REQ-CLI-12, REQ-MCP-13 and the changed archive-source, mode and paging contracts.
Use the [measure map](../swe.6-software-verification/01-requirement-verification.md) and [traceability](../traceability.md) to inspect the supporting contracts and test scopes.

## Acceptance limits

- Native non-Unix broken-response-pipe implementation and execution remain open under [transport obligations](03-open-qualification.md#transport-exits).
- Secure directory mode supports macOS/Linux/iOS/FreeBSD and refuses other platforms; only macOS execution is demonstrated.
- Diagram freshness checking is blocked by unavailable Docker; this task changes no UML sources or SVGs.
- Archive opening validates declared metadata; selected reads enforce actual per-entry guards, leaving unread payloads unverified.
- Search coverage, omitted output, excerpt completeness and sample-only detection coverage are separate claims.
- Insight conclusions apply to supported evidence layouts; unknown fields, retained incidents and unavailable clocks stay explicit gaps.
- Reference workflows corroborate source locators, artifact/resource identity, collision refusal and archive preservation; they do not replace hostile-input or platform failure checks.
- [AOSP repaired-device acceptance](03-open-qualification.md#aosp-runtime) concerns external platform candidates and remains open independently of this product's requirement assessment.

## Reuse and maintenance

Before reusing a verdict, compare the implementing path, test assertions, fixture configuration and platform with the linked execution record.
Update a verdict when its evidence no longer supports the current contract; a passing suite total alone cannot close a gap.
Record new executions outside documentation and update only the current assessment and remaining obligations here.
